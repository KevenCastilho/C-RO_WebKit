    Começando

    Download e arquivos

    Guia

    O que existe na pasta dist/, para que serve cada arquivo e como escolher.

    Conteúdo do pacote#

    Os arquivos ficam em dist/. Não há Node nem npm: é só copiar os arquivos que você precisa.

    Arquivo O que é
    c-ro-bs.css / c-ro-bs.min.css Kit + Bootstrap 5.3.8 em um CSS só. O Bootstrap fica em @layer bootstrap; o kit fica fora do layer e vence.
    c-ro-bs.js / c-ro-bs.min.js Bootstrap (bundle com Popper) + JS do kit (abas, CRO.*, select, cursor animado, favicon). Define window.bootstrap e window.CRO.
    c-ro.css / c-ro.min.css Só o kit (classes cro-* e elementos HTML nus), sem Bootstrap.
    c-ro.lite.css / c-ro.lite.min.css Kit sem as peças específicas do jogo: botão Fechar, mesbtn com ícone, barra de diálogo/tooltip, sysbox.
    c-ro.js / c-ro.min.js Só o JS do kit (sem Bootstrap). Serve para c-ro.css e c-ro.lite.css.
    fonts/ Nimbus Sans (Regular, Bold, woff2) + avisos de licença. Fica ao lado do CSS.

    Tamanhos aproximados#

    Arquivo Bruto gzip
    c-ro-bs.min.css ~1,2 MB ~150 KB
    c-ro-bs.min.js ~142 KB ~56 KB
    c-ro.min.css ~527 KB ~74 KB
    c-ro.lite.min.css ~361 KB ~59 KB
    c-ro.min.js ~62 KB ~33 KB

    O peso vem dos sprites pixel-exatos (gradientes de 1px por linha), dos ícones do jogo e dos cursores, todos embutidos como CSS/data: URI. Não há imagens externas: um CSS e um JS resolvem tudo.

    Como combinar#

    HTML
    <!-- Caso comum: Bootstrap tematizado -->
<link rel="stylesheet" href="c-ro-bs.min.css">
<script src="c-ro-bs.min.js"></script>

<!-- Só o kit, sem Bootstrap -->
<link rel="stylesheet" href="c-ro.min.css">
<script src="c-ro.min.js"></script>
    Atenção

    Não misture c-ro.css com o Bootstrap original: o kit já inclui o Bootstrap em c-ro-bs.css. Dois Bootstraps na mesma página causam conflitos.

    Usar direto do GitHub#

    O repositório é https://github.com/KevenCastilho/C-RO_WebKit. Há duas formas de usar os arquivos dele:

    1. Baixar e copiar (recomendado). Em Code → Download ZIP, copie de dist/ os arquivos que você precisa, mais a pasta fonts/. É a única forma de travar a versão, porque o repositório não usa tags: a branch main pode mudar.
    2. Apontar para o GitHub Pages. Funciona sem copiar nada, mas o endereço sempre serve a versão atual da main:
    HTML
    <link rel="stylesheet" href="https://kevencastilho.github.io/C-RO_WebKit/dist/c-ro-bs.min.css">
<script src="https://kevencastilho.github.io/C-RO_WebKit/dist/c-ro-bs.min.js"></script>

    O CSS carrega as fontes da pasta fonts/ que está ao lado dele, então elas vêm do mesmo endereço (.../dist/fonts/). Não use raw.githubusercontent.com: o GitHub serve esses arquivos como texto puro e o navegador recusa o CSS e o JS.

    Limitação

    Apontar para o Pages deixa a sua página dependente do GitHub estar no ar e de a main não mudar. Para produção, copie os arquivos.

    Versão legível x minificada#

    c-ro-bs.css e c-ro.css têm comentários e seções nomeadas (bom para estudar e depurar). Os .min.* são equivalentes; o teste de regressão garante que o minificado renderiza idêntico, pixel a pixel.
