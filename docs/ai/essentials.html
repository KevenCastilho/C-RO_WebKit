Essentials

Everything needed to produce correct code with C-RO in one page. Details per component are in the other pages of this reference.

What C-RO is

A CSS/JS kit that gives Bootstrap 5.3.8 the look of the 2002 Classic Ragnarok Online interface. It is a complete Bootstrap theme: you write normal Bootstrap markup and the CSS changes the appearance. It also provides native cro-* pieces for things Bootstrap lacks (game window with title bar, inventory slots, tree, menus, CRO.alert/confirm/prompt/menu dialogs), game cursors, and an automatic favicon. No Node, no build step is needed to use it.

Hosted copies: https://kevencastilho.github.io/C-RO_WebKit/dist/c-ro-bs.min.css, https://kevencastilho.github.io/C-RO_WebKit/dist/c-ro-bs.min.js (same folder for the other files). Keep the fonts/ folder next to the CSS: font URLs are relative to the CSS file. Do not use raw.githubusercontent.com (served as text/plain, browsers refuse it).

Never load c-ro.css together with the original Bootstrap, and never load two Bootstraps: c-ro-bs.css already contains Bootstrap.

Minimal page

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My page</title>
  <link rel="stylesheet" href="c-ro-bs.min.css">
</head>
<body>
  <button class="btn btn-primary">Hello, adventurer!</button>
  <script src="c-ro-bs.min.js"></script>
</body>
</html>

Rules that prevent most mistakes

  1. Use plain Bootstrap 5.3.8 markup for anything Bootstrap has (btn, card, modal, form-control, nav-tabs, ...). Do not invent cro-* variants of them. Components are marked Bootstrap drop-in in this reference.
  2. Only use cro-*, is-* and data-cro-* names that are documented. The full list is in Class index and data-cro-* attributes. If a class is not listed there, it does not exist.
  3. Cascade: Bootstrap is inside @layer bootstrap; the kit is outside any layer and therefore wins over Bootstrap; the site's own CSS loaded after the kit wins over the kit. Bare-element rules of the kit use :where() (zero specificity), so a simple selector like a { color: ... } overrides them without !important. Overriding a kit class needs equal or higher specificity or a later stylesheet. Do not use !important as a first resort.
  4. Customize with tokens first: redefine --cro-* custom properties on :root or on any container (full list: Tokens). Example: --cro-accent, --cro-sel-bg, --cro-field-bg, --cro-field-border, --cro-win-body, --cro-font-ui. Sprites (buttons, bars, icons, tabs) are pixel images and do not follow color tokens. Bootstrap theme colors (primary, secondary, ...) are compiled in and are not runtime tokens.
  5. Initialize what Bootstrap requires: tooltips and popovers need new bootstrap.Tooltip(el) / new bootstrap.Popover(el); toasts need bootstrap.Toast.getOrCreateInstance(el).show(). Modal, collapse, dropdown, offcanvas, tabs and carousel work through data-bs-* attributes with no script.
  6. Tabs and selects of the kit are driven by attributes: data-cro-tabs, data-cro-panels, data-cro-tab, data-cro-panel, data-cro-select. After inserting such HTML dynamically call CRO.init(root) (idempotent).
  7. Honesty labels: items marked DERIVADO or INVENTADO do not exist in the original game; do not describe them as authentic. CONFIRMADO = measured from the game's bitmaps; NÃO DETERMINADO = visual unknown, shown with the cro-undefined class (dashed gray border).
  8. Not supported: RTL (dir="rtl") and dark mode. Native popups the CSS cannot reach stay native (date/time/color pickers, datalist; plain select popups unless data-cro-select is set). Custom scrollbars only in WebKit/Blink.
  9. Cursors: the kit sets game cursors on the whole page; a cursor declared by the author always wins. The animated cursor and the automatic favicon need the JS bundle (data-cro-cursor-anim="off" and data-cro-favicon="off" on <html> disable them).
  10. Browsers: needs @layer, :where(), mask. Approximate minimums: Chrome/Edge 120, Firefox 110, Safari 16. Automated tests run only in Chromium.
